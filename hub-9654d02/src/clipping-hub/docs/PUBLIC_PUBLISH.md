# Public publish (flag off)

`CLIP_PUBLIC_PUBLISH` defaults off. With it off, Approve keeps the existing private-label behavior, and `dispatch_item` / `dispatch_platform` return `public_publish_off` without calling a runner. With it on, Approve and Approve all require `confirm_public`, the manifest hash, and each platform `row_hash`. One item hash does not authorize every platform.

Routing while `CLIP_PUBLIC_PUBLISH` is on: horror YouTube stays on MAIN. A non-Storyblocks campaign item bound to PAID and a GTA item bound to GAMING may use that channel's YouTube. Storyblocks YouTube is bound to the MAIN channel id. A wrong MAIN channel id blocks every platform row (`will_dispatch` false) and `dispatch_item` does not call a runner. Facebook may be selected for Storyblocks only while this flag is on. That is not a YouTube channel allow, and it is not a license ban while the flag is off: the label step keeps the pre-feature platform set (YouTube, TikTok, Instagram) so a Storyblocks item that includes Facebook does not become a new legacy upload. Campaign hold and deny lists also apply only while this flag is on. CoD allows TikTok and Instagram only on the public manifest. Held Alliance stays pending and its preview `ui_kind` is `held` before the hash. `#ad` is not a paid toggle. `rights_ok` must be true on a row that would upload. `campaign_terms_ok` must be true when the item is a campaign. A YouTube row with a blank or unusable `external_id` does not open a resumable session.

After a confirmed publish, the same artifact sha256 and account are not posted again unless the request sets `repost` true. An `unknown` ledger row (timeout, or accept with no permalink) stays in reconcile. A new caption changes the manifest hash and does not unlock that row.

## Sources checked this session

- YouTube Data API `videos.insert` and the resumable upload guide, both updated 2026-11-03. Insert text: "Videos uploaded from unverified API projects are not restricted to private viewing mode." `forbiddenPrivacySetting` remains a 403. `status.containsSyntheticMedia` is on the insert "you can set" list. `paidProductPlacementDetails` is a part name. The same insert and update "you can set" lists do not name `hasPaidProductPlacement`. A mock 201 that echoes it is not writable-field proof.
- Instagram Content Publishing, updated Oct 20, 2026. A public URL uses `video_url`. A local file uses `upload_type=resumable` and `POST https://rupload.facebook.com/ig-api-upload/<API_VERSION>/<IG_MEDIA_CONTAINER_ID>` with `offset` and `file_size`. Publish is `POST /<IG_ID>/media_publish` with `creation_id`.
- Facebook Reels publishing guide examples on `graph.facebook.com/v27.0`. Graph reference `is_ai_generated`: "A boolean flag for developers to self-claim whether the video was created with AI."
- Postiz public API `POST /posts` and `POST /upload`, and TikTok settings (`DIRECT_POST` versus `UPLOAD`). The agent integration list was empty.

No live upload, container create, or post was sent. Independent security review and an authorized live test are still required. Mocked adapter tests are not a live publish.

Runtime identities for Instagram, Facebook, and TikTok come only from `CLIPPING_HUB_PUBLISH_CONFIG` (default `~/.config/clipping-hub/publish-config.json`). A valid identity moves the row from "auth absent" to "disclosure readback unverified". It does not make the row public-ready. `python3 publish_readiness.py` prints counts and next steps and does not post. A missing `accounts` map is reported as `accounts_map_absent`; legacy `targets.*.yt` bindings are not copied. `python3 tools/private_proof.py` is a dry-run unless `--execute` is present. `--execute` can upload one named local sample to the pinned MAIN channel as `privacyStatus=private` with `containsSyntheticMedia=true`, then read those fields back into a separate ledger. It was not run against YouTube. It does not approve the queue or write a public post.
